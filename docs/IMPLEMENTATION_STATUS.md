|---|---|---|

| Persian and English | UI foundation implemented | RTL/LTR and language selection exist; Flutter runtime verification is pending. |
| Market feed | Implemented via public Binance adapter | Public REST candles/tickers and chart-side WebSocket source are wired; live provider connectivity from the authoring environment is not verified. |

| Economic calendar | Adapter and UI implemented | Requires valid `FINNHUB_API_KEY`; otherwise UI/API shows configuration error. Real provider connection is not verified here. |
| In-app notifications | Implemented in backend/UI source | Persisted event-driven notifications for demo events and high-impact economic events; list, event preferences and mark-as-read. Calendar event generation needs provider key and background worker. |
| Server-side FCM sender | Partially implemented | Firebase Admin sender and device-token API exist. Flutter initialization, permission handling, token fetch/registration are not implemented; end-to-end push is unavailable. |
| Academy and exams | Implemented in backend and Flutter source | 12 modules / 36 lessons / 48 question-bank items; module pass mark 75%, 20-question randomized final at 80%; Free/Pro/Premium module gates. Text content/questions are currently authored in English even when app chrome is Persian. |
| Certificate | Implemented | Unique certificate ID, HMAC signature check, public verification JSON and printable HTML page that can be saved as PDF; platform completion only, not government/professional accreditation. |
| User identity | Implemented for product routes | Argon2 password hashes, expiring signed bearer sessions and logout revocation. Full endpoint-wide access-control audit remains outstanding. |
| Binance private connection | Implemented for read-only access | Permission endpoint must explicitly confirm read enabled and trading/withdrawals disabled; secrets encrypted at rest on backend, no real orders. Live test against a real account/key was not performed. |
| Pro/Premium membership | **Demo billing enabled by default** | Membership UI calls the authenticated demo-activation route. Pro/Premium demo entitlements expire after 30 days, no money is collected, and repeated same/higher active tier does not extend expiry. Google Play purchase verification is blocked while `NEXTRADE_BILLING_MODE=demo`; real store purchase UI is not wired into this app build. |
| Backend tests | **40 passed** | Run from `backend/` with `pytest -q`. Includes demo purchase activation, idempotent expiry, upgrade, and blocking real store verification in demo mode. Tests use mocks/fixtures; they do not verify live providers or Android UI. |
| APK/AAB | Not built | No claim of a successful APK build. |

## Production blockers

1. Add authentication/authorization and enforce account ownership on every account-specific route. Until then, keep the backend private/local. Add HTTPS, rate limits, abuse controls and security review.
2. Replace SQLite with PostgreSQL and migrations for a multi-user/multi-instance deployment; add backups, retention and monitoring.
3. Install Flutter/Android SDK and run bootstrap, `flutter analyze`, widget tests, APK build and real-device tests. Finish Firebase mobile token registration before advertising push.
4. Configure and verify Finnhub from the target region; check its current data licensing/usage limits and handle stale-data status explicitly.
5. Validate market data/WebSocket reconnect behavior and indicator calculations against independent trusted references.
6. Run reproducible backtests on adequately sized history, out-of-sample analysis and walk-forward tests; inspect transaction cost assumptions and drawdowns. The current rules are not proven profitable.
7. Complete accessibility, privacy, account deletion/export, Android release signing, deployment hardening and a product security review before public release.
